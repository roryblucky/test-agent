# 11.5: Bridge existing tenant providers into v2 phases

**What to build:** Connect the existing tenant-scoped provider implementations to the new LangGraph phases through thin v2 adapters, without importing legacy Flow Engine handlers, `FlowConfig`, `FlowContext`, or executor abstractions.

**Blocked by:** 11: Add reranking.

**Status:** completed

- [x] `TenantManager` exposes a tenant-scoped provider bundle without exposing legacy orchestration objects or configuration to the graph.
- [x] A v2 retrieval adapter accepts an existing `BaseRetrieverProvider`, preserves `Document` results, and adds only v2 concerns: Artifact persistence, provenance, PhaseResult journaling, and stable Events.
- [x] A v2 reranking adapter accepts an existing `BaseRankerProvider`, passes the refined query and ordered Documents, and returns the v2 stable ranked references without changing the provider contract.
- [x] A v2 moderation adapter accepts an existing `BaseModerationProvider` and converts `ModerationResult` into the v2 phase decision and error/Event contract.
- [x] Existing GCP/Azure provider instances remain tenant-scoped and are selected through the adapter seam; mock providers remain available for tests.
- [x] Provider failures, missing tenant providers, and cross-tenant resolution are explicit and covered through the v2 API or phase seam.
- [x] Adapter tests verify that no legacy handler, `FlowConfig`, `FlowContext`, or executor object is imported by the v2 package.
