# Use PostgreSQL as the durable Conversation and checkpoint store

PostgreSQL is authoritative for Tenant-owned Conversations (including their owning Subjects), Messages, and official shared LangGraph checkpoints; each Conversation stores a stable `thread_id`, and every history or checkpoint access authorizes its Tenant and Subject ownership first. A user Message defines a Turn and its immutable Resume TTL (`resume_deadline = user_message.created_at + configured_resume_ttl`), with the same `turn_id` in the user/assistant Messages and LangGraph State, one user Message at Turn creation, one assistant Message after successful finalization, and `durability="sync"` making the latest checkpoint authoritative without an application pointer. No application-owned Run, transport Event, heartbeat, claim, lease, execution-epoch journal, or retrieval Artifact store is part of this boundary. Full retrieval chunks remain request-local and untracked; Resume rewinds to retrieval when those transient values are required. Redis is cache-only and cannot grant access, extend TTL, or override PostgreSQL state, avoiding duplicate recovery authority.
