# Use PostgreSQL as the durable Conversation and checkpoint store

PostgreSQL is authoritative for Tenant-owned Conversations (including their owning Subjects) and Messages, document/source Artifacts and provenance, and official shared LangGraph checkpoints; each Conversation stores a stable `thread_id`, and every history or checkpoint access authorizes its Tenant and Subject ownership first. A user Message defines a Turn and its immutable Resume TTL (`resume_deadline = user_message.created_at + configured_resume_ttl`), with the same `turn_id` in the user/assistant Messages and LangGraph State, one user Message at Turn creation, one assistant Message after successful finalization, and `durability="sync"` making the latest checkpoint authoritative without an application pointer. No application-owned Run, transport Event, heartbeat, claim, lease, or execution-epoch journal is part of this boundary; durable Artifact provenance (and future deterministic calculation inputs/results) remains product data, while Redis is cache-only and cannot grant access, extend TTL, or override PostgreSQL state, avoiding duplicate recovery authority.
