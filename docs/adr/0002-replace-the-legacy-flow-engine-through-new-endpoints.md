# Replace the legacy Flow Engine through new endpoints

The new LangGraph runtime is a clean-room replacement exposed through `/v2/query/stream` while the legacy endpoints temporarily retain the existing Flow Engine. A v2 streaming request starts LangGraph immediately in the FastAPI instance that receives it; normal execution is not dispatched through a durable task queue, and no blocking v2 query endpoint is provided. The v2 request and SSE wire protocol preserve the established field names, event names, and payload shapes. Before the first deployment, the History redesign intentionally supersedes the legacy arbitrary-string `sessionId` value domain: v2 `sessionId` is a PostgreSQL-generated Conversation UUID, while `clientRequestId` is the stable logical Request identity. No deployed client or stored v2 Conversation requires legacy-ID translation. Its linear baseline reproduces the business sequence user query → pre-moderation → question refinement → retrieval → reranking → LLM answer → groundedness → post-moderation → finalization before adding new agent patterns; finalization emits the compatible execution-analysis metadata but is not a financial-analysis stage. It does not reuse `FlowConfig`, step handlers, `FlowContext`, or other orchestration structures designed for the legacy engine; the legacy engine and its dedicated code are intended to be deleted after migration.
